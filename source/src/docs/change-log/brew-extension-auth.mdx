# Change log

## v0.6.0 (2026/04/07)

**Breaking changes**

- Providers are now required to implement `getAllAccounts`, `setActiveAccount` method
- First argument passed to [`AuthProvider.refresh`](:) may only contain `accountId` property
- First argument passed to [`AuthClient.logout`](:) has been changed to last authentication result previously returned by the client

See [[link]](/docs/upgrade-guide#s-upgrading-to-brew-extension-auth-0-6-x) for more details.

#### Core

- Add [`app.getAllAccounts`](:) to retrieve all accounts from providers
- [`app.acquireToken`](:) and [`app.login`](:) accepts object containing `provider` and `accountId` as argument
- `sessionResumed` and `sessionChanged` conditions are updated in [`login` event](/docs/app/auth/AuthContext#s-login-event)
- `interaction` property added for [`login`](/docs/app/auth/AuthContext#s-login-event) and [`logout` event](/docs/app/auth/AuthContext#s-logout-event)

#### Deprecations

- `interaction` parameter provided to [`AuthProvider.login`](:) and [`AuthProvider.logout`](:), use [`AuthProviderContext.interaction`](:) instead
- `singleLogout` option in [`app.logout`](:)

## v0.4.0 (2024/07/22)

**Breaking changes**
- Provider are now required to implement `getActiveAccount` and `handleLoginRedirect` methods, see [link](/docs/upgrade-guide#s-upgrading-to-brew-extension-auth-0-4-x)
- `user` property may be `null` for [`logout` event](/docs/app/auth/AuthContext#s-logout-event)

#### Core

- Fire `logout` event on app start if user was logged in in previously
- Add `sessionResumed` and `sessionChanged` properties to [`login` event](/docs/app/auth/AuthContext#s-login-event)
- Add optional `init` and `handleLoginRedirect` methods to [`AuthClient`](:) interface
- [`AuthProviderContext`](:) argument is now passed to [`AuthClient`](:)
